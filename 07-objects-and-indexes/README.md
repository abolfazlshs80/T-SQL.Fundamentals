# اشیای پایگاه داده و Indexها

## View

View یک پرس‌وجوی نام‌گذاری‌شده است که مانند یک جدول مجازی خوانده می‌شود. می‌تواند دسترسی به داده را ساده‌تر کند یا جزئیات پیاده‌سازی را از مصرف‌کننده جدا سازد.

```sql
CREATE VIEW dbo.ActiveEmployees
AS
    SELECT EmployeeId, DepartmentId, DisplayName
    FROM dbo.Employees
    WHERE IsActive = 1;
```

View معمولی به‌تنهایی کپی مستقلی از نتیجه نگهداری نمی‌کند. مجوزها و امنیت ستون‌ها را همچنان باید صریحاً طراحی و آزمایش کرد.

## Index

Index ساختاری برای یافتن ردیف‌ها با هزینهٔ کمتر است، اما فضای ذخیره‌سازی مصرف می‌کند و تغییر داده را پرهزینه‌تر می‌سازد. Index مناسب به الگوی جست‌وجو، اتصال و مرتب‌سازی وابسته است.

```sql
CREATE INDEX IX_Orders_Customer_CreatedAt
ON dbo.Orders (CustomerId, CreatedAt);
```

ترتیب ستون‌ها مهم است: ستون‌های ابتدای کلید معمولاً در جست‌وجوهای پیشوندی مفیدترند. Indexهای زیاد یا کم‌استفاده می‌توانند سرعت نوشتن و نگهداری را کاهش دهند.

## روند بررسی کارایی

1. پرس‌وجوی کند و انتظار عملکرد را مشخص کنید.
2. طرح اجرایی و تعداد واقعی ردیف‌های خوانده‌شده را بررسی کنید.
3. شرط‌ها، اتصال‌ها و Indexهای موجود را با هم بسنجید.
4. یک تغییر در هر مرحله اعمال و با دادهٔ نماینده اندازه‌گیری کنید.
5. به‌جای افزودن Index بر اساس حدس، نتیجهٔ اندازه‌گیری را ثبت کنید.
