# مدل داده و یکپارچگی

## مدل رابطه‌ای در یک نگاه

در مدل رابطه‌ای، داده‌ها در جدول‌ها نگهداری می‌شوند. هر جدول یک نوع موجودیت یا رابطه را توصیف می‌کند؛ ستون‌ها ویژگی‌ها و ردیف‌ها نمونه‌های داده‌اند. ارتباط میان جدول‌ها معمولاً با کلیدها نمایش داده می‌شود.

## کلیدها و Constraintها

- **Candidate key**: یک یا چند ستون که مقدارشان هر ردیف را یکتا می‌کند.
- **Primary key**: یکی از Candidate keyها که به‌عنوان شناسهٔ اصلی انتخاب می‌شود.
- **Alternate key**: Candidate keyهای دیگری که انتخاب نشده‌اند.
- **Foreign key**: ستونی که به کلید یک جدول دیگر ارجاع می‌دهد.
- **Constraint**: قاعده‌ای که پایگاه داده برای معتبر نگه‌داشتن مقادیر اعمال می‌کند؛ مانند نوع داده، `NOT NULL`، `UNIQUE`، `CHECK` و کلید خارجی.

نمونه:

```sql
CREATE TABLE dbo.Departments
(
    DepartmentId int          NOT NULL PRIMARY KEY,
    DepartmentName nvarchar(80) NOT NULL UNIQUE
);

CREATE TABLE dbo.Employees
(
    EmployeeId int           NOT NULL PRIMARY KEY,
    DepartmentId int         NULL,
    DisplayName nvarchar(120) NOT NULL,
    CONSTRAINT FK_Employees_Departments
        FOREIGN KEY (DepartmentId)
        REFERENCES dbo.Departments (DepartmentId)
);
```

کلید اصلی یکتایی و شناسایی ردیف را تضمین می‌کند؛ کلید خارجی از ارجاع به واحدی ناموجود جلوگیری می‌کند. اگر رابطه اختیاری باشد، ممکن است ستون خارجی `NULL` را بپذیرد.

## نرمال‌سازی

نرمال‌سازی روشی برای طراحی جدول‌هاست تا تکرار غیرضروری و ناسازگاری هنگام درج، ویرایش یا حذف کاهش پیدا کند.

- **1NF**: هر خانه یک مقدار قابل‌استفاده در همان ستون دارد و ردیف‌ها قابل تشخیص یکتا هستند.
- **2NF**: جدول ابتدا در 1NF است و هر ویژگی غیرکلیدی به تمام کلید مرکب وابسته است، نه فقط بخشی از آن.
- **3NF**: جدول در 2NF است و ویژگی‌های غیرکلیدی به‌طور غیرمستقیم از طریق ویژگی غیرکلیدی دیگری به کلید وابسته نیستند.

برای نمونه، اگر هر سفارش چند قلم کالا داشته باشد، تاریخ سفارش معمولاً به خود سفارش وابسته است؛ مقادیر اقلام نیز به ترکیب سفارش و کالا وابسته‌اند. جداسازی سرآیند سفارش از ردیف‌های سفارش، از تکرار تاریخ در هر قلم جلوگیری می‌کند.

## چک‌لیست طراحی

1. برای هر جدول، مفهوم واحد و کلید اصلی را مشخص کنید.
2. نوع داده، امکان `NULL` و محدودیت‌های یکتایی را آگاهانه انتخاب کنید.
3. ارتباط‌ها را با Foreign key مدل کنید.
4. در جدول‌های دارای کلید مرکب، وابستگی هر ستون را جداگانه بررسی کنید.
5. Denormalization را فقط با دلیل روشن و پس از اندازه‌گیری کارایی در نظر بگیرید.
