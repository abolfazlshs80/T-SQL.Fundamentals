# اتصال جدول‌ها و تجمیع

## اتصال رابطه‌ها

`JOIN` ردیف‌های دو منبع را بر اساس یک شرط مرتبط می‌کند. معمولاً شرط اتصال، کلید اصلی یک جدول را با کلید خارجی جدول دیگر برابر می‌گیرد.

```sql
SELECT e.EmployeeId, e.DisplayName, d.DepartmentName
FROM dbo.Employees AS e
LEFT JOIN dbo.Departments AS d
    ON d.DepartmentId = e.DepartmentId;
```

- `INNER JOIN` فقط جفت‌های منطبق را برمی‌گرداند.
- `LEFT JOIN` همهٔ ردیف‌های سمت چپ را نگه می‌دارد؛ برای موردهای بی‌جفت، ستون‌های سمت راست `NULL` می‌شوند.
- `RIGHT JOIN` و `FULL JOIN` نیز وجود دارند، اما اغلب می‌توان ساختار را با جابه‌جایی سمت‌ها خواناتر کرد.

شرط اتصال نادرست یا ناقص ممکن است ردیف‌ها را چندبرابر کند. پیش از افزودن اتصال، یکتایی کلید و تعداد مورد انتظار ردیف‌های خروجی را بررسی کنید.

## تجمیع

توابعی مانند `COUNT`, `SUM`, `AVG`, `MIN` و `MAX` چند ردیف را به مقدار خلاصه تبدیل می‌کنند. `GROUP BY` مشخص می‌کند خلاصه برای کدام گروه‌ها محاسبه شود و `HAVING` گروه‌ها را پس از تجمیع فیلتر می‌کند.

```sql
SELECT DepartmentId, COUNT(*) AS EmployeeCount
FROM dbo.Employees
WHERE IsActive = 1
GROUP BY DepartmentId
HAVING COUNT(*) >= 5;
```

`WHERE` روی ردیف‌های ورودی اعمال می‌شود؛ `HAVING` روی نتیجهٔ گروه‌بندی‌شده. ستون خروجی غیرتجمیعی باید با قواعد گروه‌بندی سازگار باشد.

## عملگرهای مجموعه‌ای

`UNION` نتیجهٔ دو پرس‌وجو را ترکیب و ردیف‌های تکراری را حذف می‌کند؛ `UNION ALL` حذف تکراری انجام نمی‌دهد و معمولاً هزینهٔ کمتری دارد. هر دو طرف باید تعداد ستون و نوع‌های سازگار داشته باشند.
